# 领域约定

白玉蟹联合品控结算链围绕**塘口、养殖户、苗种批次、捕捞批次**四条主线保存可核对的业务记录。
外部主体使用不含真实身份信息的稳定引用编号，时间采用带偏移量的 ISO 8601 字符串，
材料只保存受控引用和 `sha256` 摘要。

交换事件包含 `event_id`、`source_ref`、`source_sequence`、`subject_ref`、
`occurred_at` 和 `payload_digest`。来源序号只在同一来源内严格递增（拒绝乱序、重复与缺口），
接收方必须保留原始发生时间，不得用到达时间覆盖。示例内容仅用于说明字段形状，
不代表真实人员、机构或业务结论。

## 主线与标识

| 主线 | 关键对象 | 标识示例 |
|---|---|---|
| 塘口 | 基地 `base` → 水体 `water_body` → 塘口 `pond`（面积、承包户） | `POND-1` / `HZ-001` |
| 养殖户 | 农户 `farmer`、合同版本 `contract`、结算 `settlement` | `F-1` / `CT-1` v1 |
| 苗种批次 | `seed_lot`、放养 `stocking` | `SEED-1` |
| 捕捞批次 | 起捕 `harvest_batch` → 批次树 `batch` → 分级 `grade_record` | `H-1` / `B-H-1` |

一个起捕批生成一个根批次 `B-{harvest_id}`；**分级与装运拆分都生成 `SPLIT` 子批**，
子批挂 `parent_batch_id` 与 `split_group_id`，并冗余 `root_harvest_id` 便于全树查询；
退货生成 `RETURN` 批，挂 `origin_batch_id` 指回原批。

## 投入、指导与认证

- 投入品 `material` 受控分类（饲料/兽药/肥料/消毒剂/其他）；非有机许可的兽药、消毒剂
  在登记施用时直接被拒绝。
- 技术指导 `guidance` 只能由 `technician` 角色记录。
- 有机认证 `certification` 可挂在基地/水体/塘口/农户上，有生效与失效时间；
  **起捕时塘口或所属水体必须存在有效认证**，否则不能进入高价收购链。

## 五重检测与定向冻结

检测环节 `stage` 固定为：`SEED`（苗种）、`WATER`（水体）、`INPUT`（投入品）、
`PRODUCT`（成品）、`EXPORT`（出口）。

检测 `FAIL` 后由**督导 supervisor** 创建冻结单，冻结范围按规则推导而非全库冻结：

- 指定水体 → 该水体下所有塘口的全部批次（含拆分子批）；
- 指定批次 → 该批及其拆分树下游全部子批；
- 其他水体、其他批次的销售与生产不受影响。

冻结单的后续动作由**不同角色**签署，且签署人不得与前序动作同人：

| 动作 | 角色 | 约束 |
|---|---|---|
| `FREEZE` | supervisor | 仅 `FAIL` 检测可发起 |
| `RETEST` | inspector | 可多次；不得是冻结创建人 |
| `RELEASE` | reviewer | 最近一次复检必须 `PASS`；不得是冻结人或复检人 |
| `DESTROY` | reviewer | 复检仍不合格；不得是冻结人或复检人 |

销毁时核销批次中未装运、未拆出的重量，同步释放该批未装运的柜预留，
已出库部分不属于冻结范围。冻结中的批次禁止分配、出库、分级、拆分；
冻结中的水体禁止新起捕。

## 批次守恒

每个批次维护 `qty_kg = allocated_kg + shipped_kg + destroyed_kg + split_out_kg + 现存可支配`，
由表内 CHECK 约束兜底。每次数量变化都追加一条 `stock_movement`（只追加，触发器禁止改删）：

- 分级/拆分：父批一笔 `SPLIT_OUT(-)`，每个子批一笔 `SPLIT_IN(+)`，
  拆出重量必须等于子批重量之和；
- 出口分配：`ALLOCATE_HOLD(-)`；释放：`ALLOC_RELEASE(+)`；
- 发运：先 `ALLOC_RELEASE(+)` 再 `SHIP(-)`（预留转实发，两笔净额为零）；
- 销毁：`DESTROY(-)`；退货：新批 `RETURN_IN(+)`。

`GET /v1/consistency` 按上述恒等式逐批、逐拆分组、逐柜、逐结算行核对，
任何不为零的差异都会列出（拆分不平衡、超卖、分级超起捕、柜超量、冲正超额、
移动账实不符、冻结状态漂移）。

## 出口采购与不超卖

出口订单按"柜量 × 每柜公斤数"生成柜 `order_container`，订单携带质量条件
（等级、要求的检测环节、当前有机认证）。分配 `batch_allocation` 把多个批次的
可用库存预留给某个柜：

- 所有写操作在 `BEGIN IMMEDIATE` 事务内执行；
- 库存扣减使用**单条条件 UPDATE**（`qty - 已分 - 已装 - 销毁 - 拆出 >= 本次量`
  时才生效，`rowcount` 必须为 1），因此并发分配只会有一方成功，结构上杜绝超卖；
- 柜容量、等级、检测/认证条件任一不满足则整笔回滚。

发运后登记交付回执 `delivery_receipt`，实收不得超过柜已装数量；
退货不得超过该批在该柜的"已装 − 已退"。订单可用性视图联动目标量、预留量、
已装量、退货量与当前同等级可用库存。

## 合同版本、结算与冲正

合同按农户版本化（`version` 单调递增，新版本生效自动置旧版为非当前）。
结算按**生成时的当前合同版本**固化等级单价与帮扶加价：

```
每行金额 = 分级重量 × (等级单价 + 帮扶加价/公斤)
```

结算行保存合同版本、单价、加价与金额，合同事后改版不影响已生成结算；
`GET /v1/settlements/{id}/explain` 逐行给出计算公式、冲正记录与净额，
可回答"每笔结算为何得到该金额"。

台账 `ledger_entry` 为只追加表（触发器禁止 UPDATE/DELETE）：

- 确认结算写入 `NORMAL` 行；
- 退货或更正只追加 `REVERSAL` 负向行（金额、重量为负，`reverses_entry_id`
  指向原行，可挂 `SALES_RETURN` 引用），**绝不修改原账**；
- 冲正重量不得超过原结算重量，可整笔或部分冲正。

## 追溯

市场抽检样品 `market_sample` 挂在具体批次上。`GET /v1/samples/{id}/trace`
沿批次树上溯到起捕批，再到塘口、水体、养殖户、苗种批次，并聚合：

- 塘口全部放养、投入品施用、技术指导、水体/塘口检测、有机认证；
- 该起捕批全树的成品检测；
- 分配 → 柜 → 订单/客户 → 发运 → 交付回执 → 退货的完整流向。

由此可回答"一只市场抽检样品来自哪片塘、接受过哪些投入和检测"。

## 角色

`manager` 管理、`inspector` 检测、`reviewer` 审核（解封/销毁）、
`supervisor` 督导（冻结）、`technician` 技术员、`sales` 外销、`finance` 财务。
角色校验在服务层强制执行，错误角色返回 403。
