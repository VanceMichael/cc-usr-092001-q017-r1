# 白玉蟹联合品控结算链

湖州、苏州近两千亩白玉蟹基地的后端系统：以**塘口、养殖户、苗种批次、捕捞批次**为主线，
记录投入品、技术指导、五重检测、起捕、分级与流向；批次拆分装运后数量仍然守恒可追溯；
检测不合格只定向冻结相关水体与关联批次，复检、解封、销毁由不同角色签署；
外商柜量与实际可用库存联动，并发分配不超卖；农户结算按合同版本、等级、重量与
帮扶加价生成，退货只做冲正不改原账。

纯 Python 标准库实现（`http.server` + SQLite），无额外运行时依赖。

## 能力一览

- **主线档案**：基地/水体/塘口/农户、苗种批次与放养、投入品施用（有机禁用拦截）、
  技术指导、有机认证（起捕时强制有效）。
- **五重检测**：苗种、水体、投入品、成品、出口五个环节。
- **定向冻结**：水体→其下塘口全树批次；批次→其下游拆分子批。冻结由督导发起，
  复检（检测员）、解封/销毁（审核人）角色分离且签署人互不相同。
- **批次守恒**：分级与装运拆分形成批次树，库存移动只追加；
  起捕量 = 分级量、父批拆出 = 子批合计、批次占用不超总量，均由约束与核对保证。
- **出口联动**：订单柜量与质量条件，多批次并发分配用条件 UPDATE 原子扣减，绝不超卖；
  发运、交付回执、退货入库（形成 RETURN 批）全链记录。
- **结算可解释**：合同版本化，金额 = 重量 ×（等级单价 + 帮扶加价），
  单价与版本固化在结算行；台账只追加，退货以 REVERSAL 负向行冲正。
- **双向追溯**：一只市场抽检样品可追到塘口、水体、养殖户、苗种、全部投入/指导/检测
  与出口流向；每笔结算可给出逐行计算公式与净额。
- **一致性核对**：`GET /v1/consistency` 输出全部不平衡项。

## 目录

- `src/schema.py` 数据库结构（含只追加触发器）
- `src/db.py` 连接、初始化与 `BEGIN IMMEDIATE` 事务
- `src/domain/` 领域服务：`masters` `quality` `produce` `trading` `settlement` `trace`
- `src/api.py` HTTP 路由
- `docs/domain.md` 领域规则；`docs/api.md` 接口清单
- `contracts/` 外部交换字段示例
- `tests/` 35 个行为测试（含多线程不超卖、HTTP 端到端）

## 运行

```bash
make test      # 运行全部测试
make migrate   # 初始化本地 SQLite（DATABASE_PATH，默认 data/app.sqlite3）
make run       # 启动服务，默认 8080，健康检查 /health
```

接口统一在 `/v1/` 前缀下，详见 `docs/api.md`。配置通过环境变量传入
（`PORT`、`DATABASE_PATH`），敏感值和本地数据库文件不得提交到仓库。
